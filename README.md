# Dev By Amir — پورتفولیوی امیرحسین محمدرفیع

پورتفولیوی تک‌صفحه‌ای فارسی، راست‌به‌چپ و واکنش‌گرا برای معرفی مهارت‌ها، نمونه‌کارها و مسیر همکاری. پروژه بدون فریم‌ورک و بدون مرحلهٔ build ساخته شده تا سبک، قابل‌فهم و قابل‌اجرا با یک وب‌سرور ساده باشد.

## وضعیت فعلی

- نسخهٔ **Electric** برای اولین بازدید فعال است و کاربر می‌تواند بین طرح‌های **استودیو، تحریری و الکتریک** جابه‌جا شود.
- انتخاب طرح در `localStorage` ذخیره می‌شود.
- تایپوگرافی متن و رابط با **IRANSansX FaNum** و تیترهای نمایشی با **Rokh** به‌صورت محلی و WOFF2 بارگیری می‌شوند.
- تصویر پروفایل کاری در هویت بصری Electric، لوگوی صفحه و بخش Hero استفاده شده است.
- ویرایشگر زندهٔ HTML/CSS/JavaScript با `iframe` ایزوله، فیلتر نمونه‌کارها، دیالوگ جزئیات پروژه و منوی موبایل فعال هستند.
- نسخهٔ Electric دارای سلسله‌مراتب بصری تقویت‌شده، هدف لمسی مناسب موبایل، حالت فعال ناوبری و پیش‌نمایش فشرده‌تر Live Code است.
- ناوبری موبایل و لینک «بازگشت به بالا» در Chrome بررسی شده‌اند؛ در عرض‌های ۳۲۰، ۳۹۰ و ۷۶۸ پیکسل سرریز افقی مشاهده نشد.
- سطوح بصری نسخهٔ Electric با سیستم مشخص برای `overflow`، سایه، لایه‌بندی، گوشه‌ها و حالت `focus-visible` یکدست شده‌اند؛ کارت‌ها افکت نور ظریف دارند اما ساختار محتوا را تحت‌تأثیر قرار نمی‌دهند.
- کارت‌های نمونه‌کار در هر سه تم متن توضیح و فرادادهٔ خواناتر، فاصله‌گذاری منظم، برچسب‌های واضح‌تر و دکمهٔ جزئیات ۴۴ پیکسلی دارند. در Electric درخشش کوتاه تصویر فقط با hover یا فوکوس و بدون درخواست حرکت کاهیده اجرا می‌شود.
- فایل‌های CSS با query version در `index.html` بارگیری می‌شوند تا بعد از تغییرات طراحی، cache قدیمی مرورگر باعث نمایش نسخهٔ قبلی نشود.

## معماری پروژه

1. `index.html` ساختار معنایی، محتوای فارسی، ARIA و بخش‌های صفحه را تعریف می‌کند.
2. `styles.css` طراحی پایه، layout، responsive breakpointها، کامپوننت‌های عمومی و Live Code را نگه می‌دارد.
3. `designs.css` لایهٔ تم است و تفاوت‌های Studio، Editorial و Electric را مدیریت می‌کند.
4. `script.js` رفتارهای تعاملی DOM را مدیریت می‌کند و دادهٔ پروژه‌ها را از markup جدا نگه می‌دارد.
5. `assets/` تصاویر، favicon و فونت‌های مورد استفادهٔ مستقیم سایت را شامل می‌شود.

## فناوری‌ها و تصمیم‌های فنی

- HTML5 معنایی با ساختار RTL، لینک عبور به محتوا، برچسب‌های ARIA و دیالوگ بومی مرورگر.
- CSS خالص با Grid، Flexbox، media query، `@font-face`، انیمیشن کنترل‌شده و پشتیبانی از `prefers-reduced-motion`؛ بدون فریم‌ورک یا build step.
- JavaScript خالص برای انتخاب تم، فیلتر پروژه، دیالوگ، منوی موبایل، نمایان‌سازی در اسکرول و Live Editor؛ تنظیمات تم در `localStorage` ذخیره می‌شوند.
- پیش‌نمایش کد در `iframe` دارای `sandbox="allow-scripts"` اجرا می‌شود. CSS و JavaScript نمونه در textareaها قابل‌ویرایش‌اند و کد اضافی پشت صحنه بر خروجی تحمیل نمی‌شود.

## توابع و منطق JavaScript

### `updateProgressBar()`
درصد پیمایش را از ارتفاع سند محاسبه و عرض نوار پیشرفت بالای صفحه را به‌روزرسانی می‌کند.

### `selectDesign(design)`
تم معتبر را روی `body` اعمال می‌کند، `theme-color` مرورگر و وضعیت `aria-pressed` دکمه‌ها را تغییر می‌دهد و انتخاب را در `localStorage` ذخیره می‌کند.

### `applyProjectFilter(category, activeButton)`
وضعیت فعال دکمه‌های فیلتر را به‌روزرسانی می‌کند و کارت‌ها را بر اساس `data-category` نمایش یا مخفی می‌کند.

### دادهٔ `projects`
عنوان، توضیح، نوع، قابلیت‌ها، برچسب‌ها و لینک منبع شش پروژه را نگه می‌دارد و هنگام باز شدن دیالوگ مصرف می‌شود.

### `createListItems(items, tagName)`
برای قابلیت‌ها و tagهای پروژه، عناصر DOM را با `textContent` می‌سازد تا محتوای واردشده به‌صورت امن نمایش داده شود.

### `openProjectDialog(trigger)`
پروژهٔ مرتبط با دکمه را پیدا می‌کند، محتوای دیالوگ را پر می‌کند، لینک منبع را تنظیم می‌کند و دیالوگ را باز می‌کند.

### مدیریت `project-dialog`
اطلاعات پروژه را با `textContent` در دیالوگ قرار می‌دهد، قابلیت‌ها و tagها را می‌سازد، لینک GitHub را فقط در صورت وجود نمایش می‌دهد و بعد از بسته‌شدن فوکوس را به trigger برمی‌گرداند.

### مدیریت منوی موبایل
تابع `setMobileMenu(isOpen)`، `aria-expanded`، `aria-label`، ویژگی `hidden` و وضعیت باز/بستهٔ منوی موبایل را کنترل می‌کند.

### `setActiveSection(sectionId)` و `updateActiveSection()`
لینک بخش فعلی را هنگام اسکرول مشخص می‌کنند، `aria-current="location"` را تنظیم می‌کنند و در بالای صفحه همهٔ لینک‌های بخش‌ها را غیرفعال نگه می‌دارند.

### انیمیشن مهارت‌ها
تابع `initializeSkills()` با `IntersectionObserver` نوارها را هنگام ورود به viewport فعال می‌کند و در مرورگرهای بدون این API، حالت نهایی را بدون شکست اعمال می‌کند.

### ورود عناصر هنگام اسکرول
تابع `initializeScrollReveals()` تیتر سکشن‌ها، کارت پروژه‌ها، پنل تماس و ویرایشگر زنده را فقط یک‌بار هنگام نزدیک‌شدن به viewport آشکار می‌کند. انیمیشن‌ها با `transform` و `opacity` اجرا می‌شوند و در حالت `prefers-reduced-motion` غیرفعال می‌مانند. pulse نشان وضعیت و نور پس‌زمینهٔ Hero نیز با CSS اجرا می‌شوند؛ حرکت تنفسی تصویر Hero فقط در دسکتاپ فعال است.

### `setActiveEditorTab(activeTab)`
تب فعال و پنل متناظر HTML، CSS یا JavaScript را تغییر می‌دهد و `aria-pressed` را هماهنگ می‌کند.

### `runCode()`
محتوای سه ویرایشگر را ترکیب می‌کند، CSS و JavaScript را داخل HTML قرار می‌دهد و با `srcdoc` در `iframe` دارای `sandbox="allow-scripts"` نمایش می‌دهد. تگ‌های پایانی داخل متن کد escape می‌شوند تا سند پیش‌نمایش زودتر بسته نشود. اجرا با دکمه، debounce و میانبر `Ctrl/Cmd + Enter` انجام می‌شود.

## فونت‌ها و مجوز استفاده

فونت‌ها در این مسیر بررسی شدند:

```text
D:\Front-End Develop\My Fonts\farsi
```

- **IranSansX(Pro):** پوشهٔ استخراج‌شده، `licenses.pdf`، نسخهٔ Variable و وب‌فونت‌های WOFF2 دارد. نسخهٔ Farsi Numerals برای متن فارسی استفاده شده است.
- **Rokh Economic:** سه وب‌فونت WOFF2 از بستهٔ ارائه‌شده در `assets/fonts/rokh/` قرار گرفت و فقط برای تیترها استفاده می‌شود. `FontLicense.txt` همراهشان است، اما کد شش‌رقمی مجوز در نسخهٔ ارائه‌شده هنوز جای‌نگهدار است؛ پیش از انتشار عمومی، مالک پروژه باید مجوز را در همان فایل تکمیل و اجازهٔ انتشار فونت را بررسی کند.
- **Shabnam:** در ZIP فایل‌های WOFF2 و راهنمای کوتاه وجود دارد، اما برای طراحی فعلی انتخاب نشده چون IRANSansX وزن‌ها و خوانایی مناسب‌تری دارد.

> خرید فونت الزاماً به‌معنی مجوز انتشار فایل فونت در مخزن عمومی یا استفاده در چند محصول نیست. پیش از انتشار آنلاین، شرایط همان لایسنس و کد خرید را بررسی کنید.

فونت **Shabnam** نیز در بستهٔ محلی موجود بود، اما برای جلوگیری از بارگیری فونت سوم و حفظ انسجام صفحه وارد پروژه نشد. انتخاب فعلی: IRANSansX برای متن و کنترل‌ها؛ Rokh برای تیترهای هویتی.

## اجرا

در ریشهٔ پروژه اجرا کنید:

```powershell
python -m http.server 8000
```

سپس در Chrome باز کنید:

```text
http://localhost:8000/
```

باز کردن مستقیم `index.html` برای بخش‌های استاتیک ممکن است، اما وب‌سرور محلی برای بارگذاری فونت، iframe و رفتار یکسان مرورگر مطمئن‌تر است.

## راهنمای نگهداری کد

- متن فارسی و ساختار semantic در `index.html` بماند؛ استایل inline اضافه نشود.
- تغییرات عمومی layout در `styles.css` و تفاوت‌های تم در `designs.css` انجام شود.
- منطق تعامل فقط در `script.js` باشد؛ پروژهٔ جدید به دادهٔ `projects` و markup مرتبط اضافه شود.
- برای متن کاربر از `textContent` استفاده شود؛ HTML خام فقط در محیط آزمایشی Live Code وارد `srcdoc` می‌شود.
- تصاویر و فونت‌های بزرگ بدون نیاز کپی نشوند و پیش از انتشار، حجم و مجوز آن‌ها بررسی شود.
- پس از تغییر JavaScript، `node --check script.js` و پس از تغییر UI، تست دسکتاپ و موبایل اجرا شود.

## اعتبارسنجی انجام‌شده

- بررسی نحوی JavaScript با `node --check script.js`.
- بررسی parse شدن HTML با `html.parser` پایتون.
- بررسی بارگذاری IRANSansX با `document.fonts.check()` در Chrome.
- تست تم‌ها، فیلتر پروژه‌ها، دیالوگ، منوی موبایل و Live Code در Chrome.
- تست responsive در عرض‌های ۳۲۰، ۳۹۰ و ۷۶۸ پیکسل و بررسی نبودن horizontal overflow.
- ممیزی alt تصاویر، نوع دکمه‌ها، وضعیت‌های ARIA و scroll-spy ناوبری.

## قابلیت دو‌زبانه

- زبان پیش‌فرض فارسی است و با دکمهٔ `EN ↔ FA` در Header می‌توان رابط را به انگلیسی تغییر داد.
- انتخاب زبان در `localStorage` با کلید `portfolio-language` ذخیره می‌شود.
- هنگام تغییر زبان، `lang` و `dir` سند نیز تغییر می‌کنند: فارسی `fa/rtl` و انگلیسی `en/ltr`.
- متن‌های اصلی رابط، ناوبری، معرفی، فیلترها، کارت‌های پروژه و وضعیت‌های تعاملی ترجمه می‌شوند؛ متن‌های داخل mockupهای تصویری عمداً بخشی از طراحی نمونه باقی می‌مانند.
- محتوای ترجمه در `script.js` متمرکز شده تا توسعهٔ زبان سوم یا اصلاح متن‌ها بدون بازنویسی HTML امکان‌پذیر باشد.

## تحویل و اعتبارسنجی نهایی

- `node --check script.js` موفق است.
- ساختار `index.html` با parser استاندارد HTML بررسی شده است.
- سرور محلی با پاسخ HTTP `200` در دسترس است.
- تست‌های قبلی Chrome برای Electric شامل responsive، فیلتر پروژه، منوی موبایل، مودال و Live Preview موفق بوده‌اند.
- تست تب جدید Chrome در تاریخ ۳ اکتبر ۲۰۲۶ به‌دلیل timeout اتصال محیط مرورگر کامل نشد؛ این موضوع به کد پروژه مربوط نیست و سرور محلی پاسخ صحیح می‌دهد.
